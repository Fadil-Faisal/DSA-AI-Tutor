1. Project Overview
The Adaptive DSA Tutor Agent is a fully autonomous AI agent that builds a real-time cognitive model of each student. It tracks every answer, hesitation, and wrong turn, then continuously decides what to teach next, how hard to push, when to give hints, and when a student is ready to move on.
This document is the complete frontend implementation guide for Hamood Ayoob Khan. It covers the project structure, every page and component, state management, API integration, the two-stage explanation system (Simple / Complex mode), UI/UX guidelines, and a step-by-step build checklist.

All tools are free-tier or open source.

4. Pages — Detailed Breakdown
4.1 Landing + Onboarding Quiz (app/page.tsx)
The first screen the user sees. It bootstraps the learner model with a 5-question rapid-fire quiz covering Arrays, Trees, Graphs, Recursion, and DP. Tracks both correctness and time taken to set initial confidence scores.
Simple vs Complex Mode — The Two-Stage Explanation System
This is one of the key differentiators of this project. When a user selects their mode at the start, it persists in Zustand state and controls every AI prompt sent throughout the session.
Implementation: Store mode in Zustand as learnerStore.explanationMode. Every API call to /api/agent and /api/hint includes this value. The backend appends the appropriate persona instruction to the AI system prompt.

6. State Management — Zustand Store
A single Zustand store manages all client-side state. Immer is used for clean nested updates to the learner model.
// store/learnerStore.ts
interface LearnerStore {
  // Identity
  sessionId: string;
  explanationMode: 'simple' | 'complex';  // THE TWO-STAGE SYSTEM
  // Learner model (mirrors Supabase learner_profiles)
  confidence: {
    arrays: number;      trees: number;      graphs: number;
    dp: number;          recursion: number;  sorting: number;
    searching: number;   strings: number;    heaps: number;
    linkedLists: number;
  };
  // Current session
  currentProblem: Problem | null;
  currentHintLevel: 0 | 1 | 2 | 3;
  timerStarted: boolean;
  timerSeconds: number;
  // Agent state
  agentReasoning: string;
  agentLoading: boolean;
  // Actions
  setExplanationMode: (mode: 'simple' | 'complex') => void;
  updateConfidence: (topic: string, value: number) => void;
  setCurrentProblem: (problem: Problem) => void;
  incrementHintLevel: () => void;
  setAgentReasoning: (text: string) => void;
}
7. API Integration — What the Frontend Calls
The frontend never calls Groq or Gemini directly. All AI calls go through Next.js API routes. The explanationMode is always sent with every request.
Example: Fetching Next Problem with Mode
// hooks/useAgent.ts
async function fetchNextProblem() {
  const { sessionId, confidence, explanationMode } = useLearnerStore.getState();
  const res = await fetch('/api/agent', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ sessionId, confidence, explanationMode }),
  });
  const { problem, reasoning } = await res.json();
  useLearnerStore.getState().setCurrentProblem(problem);
  useLearnerStore.getState().setAgentReasoning(reasoning);
}
8. Supabase Realtime — Multiplayer Sync
Multiplayer uses Supabase Realtime to sync code and state between two browser windows. No Pusher or Socket.io needed.
// In [roomCode]/page.tsx
const supabase = createClient();
// Subscribe to room member changes
const channel = supabase
  .channel(`room:${roomCode}`)
  .on('postgres_changes', {
    event: 'UPDATE',
    schema: 'public',
    table: 'room_members',
    filter: `room_id=eq.${roomId}`,
  }, (payload) => {
    // Update opponent's code in Monaco editor
    setOpponentCode(payload.new.current_code);
    setOpponentCursor(payload.new.cursor_position);
  })
  .subscribe();
// Send own code changes
const handleCodeChange = (code: string) => {
  debouncedUpdate(() => {
    supabase.from('room_members').update({
      current_code: code
    }).eq('session_id', sessionId);
  }, 300);  // debounce 300ms
};
